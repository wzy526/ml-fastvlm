# Qwen2.5-VL-7B learned DAT implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Port the current Qwen3.5 where-head → crop density → inverse-CDF mosaic → global M-RoPE route to Qwen2.5-VL-7B, including training and evaluation.

**Architecture:** Keep the sampler and head architectures shared. Isolate backbone loading, visual geometry, merged ViT output and RoPE APIs in an adapter. Preserve existing Qwen3.5 entry points and defaults; use the official Qwen2.5-VL model for the new route, without legacy attention injection.

**Tech stack:** PyTorch, Transformers 5.6.1 (repository lock), torchrun, lmms-eval plugin.

**Spec:** User confirmed the latest where-head / crop + DAT route. Training data and benchmark column definitions were not supplied; expose paths and use the existing Visual-CoT / RefCOCO / COCO recipe. Do not claim reproduced paper scores.

## Constraints and design decisions

- Derive patch size, temporal size, merge size and hidden width from the model/processor. Qwen2.5 7B uses 14×2=28 pixels per merged image token; Qwen3.5 uses 16×2=32.
- Keep the current learned density, adaptive window, sampled token budgets and global positions. Do not copy Gated DeltaNet cache patches into Qwen2.5.
- Re-train where and density heads on the 7B backbone. Existing Qwen3.5 head tensors have incompatible input widths.
- Provide a frozen official-backbone route and optional answer SFT using the existing trainer. No training run or benchmark claim without real weights/data/GPU evidence.
- Reuse the current clean checkout; keep the changes uncommitted for review.
